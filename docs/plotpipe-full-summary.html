01 — Overview

What is PlotTeaFiles Studio?

PlotTeaFiles Studio is a locally-run automation pipeline that converts a plain English story script into a fully produced vertical video — complete with voiceover, word-level captions, AI-generated cinematic images, and a polished MP4 output suitable for Instagram Reels, YouTube Shorts, or TikTok.

The project was originally scaffolded by an AI coding assistant (Codex) as a CLI tool called PlotPipe. The June 2026 session transformed it into a full-stack product with a web-based Studio UI, live progress tracking, model selection, and a complete visual redesign.

The Pipeline — Step by Step

1
Script Input User pastes a plain English story into the Studio UI. GPT converts it to a structured StoryScript JSON with segments, dialogue, and mood.
2
Voiceover Generation OpenAI TTS (gpt-4o-mini-tts) or ElevenLabs generates a per-segment narration MP3 from the script text.
3
Caption Transcription OpenAI Whisper transcribes each audio file into word-level timestamps — used for animated karaoke-style captions in the final video.
4
Image Generation OpenAI gpt-image-2 generates cinematic 1024×1536 portrait images for each shot in each segment. Multiple images per segment create visual variety during narration.
5
Remotion Render Remotion (React-based video engine) assembles all assets — audio, images, captions — and renders the final MP4 at full quality.
6
Output & Download The completed MP4 is saved to out/studio/ and plotteafiles/, and a download link appears in the Studio UI.

Key Architecture Decision: Local Spawn Pattern

The Studio web UI does not call the pipeline directly. Instead, it spawns the PlotPipe CLI as a child process using Node.js spawn(). This means:

  • The full pipeline code doesn't need to run inside Next.js
  • Stdout/stderr from the CLI is piped back to both the terminal and the progress tracker
  • Jobs can be cancelled by killing the child process
  • The same CLI can be used standalone (no web UI needed)

04 — Challenges & Setbacks

8 Challenges Overcome

Every build session has its walls. Here's every problem hit, and how each one was solved.

1 — Session Context Lost
User accidentally opened the project folder in a different Claude session, wiping the active conversation. Three prior upgrades were mid-flight with no written record.
Fix: Ran git diff HEAD across the 5 modified files. All uncommitted changes were visible in the working tree. Reconstructed the full picture from the diff and briefed the user.
2 — VS Code Python .env Warning
VS Code showed "python.terminal.useEnvFile is disabled" when the FAL_KEY was added. User thought this would prevent the key from loading.
Fix: The warning is from the Python VS Code extension — completely irrelevant to Node.js. Next.js reads .env automatically via dotenv. No action needed.
3 — fal.ai Balance Exhausted
FAL_KEY was valid and the connection worked, but the API returned "Exhausted balance. Top up at fal.ai/dashboard/billing." FLUX Pro costs ~$0.05/image.
Fix: Parked FLUX entirely. Kept the full integration code in place — it will work immediately when the user tops up their fal.ai balance.
4 — Wrong npm Command
Running npm run dev launched the CLI, not the web server. This caused confusion about why the Studio UI wasn't available.
Fix: Correct commands are npm run web:dev (hot reload) or npm run web:build + npm run web:start (production, lower RAM). Documented in memory.
5 — Render Appeared Stuck at 58%
Progress bar stopped at 58% during image generation. No terminal logs visible. User suspected the job had frozen or crashed silently.
Fix (immediate): Checked localhost:3000/api/jobs — status was still 'running'. Job was alive. Fix (permanent): Added stdout/stderr piping from child process to terminal. Root cause: gpt-image-2 High quality × 15 images = 5–15 minutes. Normal.
6 — Port 3000 EADDRINUSE
After a rebuild, npm run web:start failed: "Error: address already in use :::3000". The previous server process hadn't been killed before the rebuild.
Fix: netstat -ano | findstr :3000 revealed PIDs. Killed them with Stop-Process -Id <PID> -Force in PowerShell. Server started cleanly after.
7 — Edit Tool "File Not Read" Errors
Multiple Edit tool calls failed mid-session because the target files hadn't been read into context first. The tool requires a prior Read call before any edit.
Fix: Always Read before Edit. Established as a working discipline for subsequent changes in the session.
8 — Playwright file:// Protocol Blocked
Tried to open mockup HTML files via file:/// URL in Playwright for the UI comparison exercise. The protocol was blocked.
Fix: Navigated to about:blank instead, then injected the full HTML directly via browser_evaluate with document.write(). Worked perfectly for all 3 mockup directions.

Recommended Strategy

All images are generated at 1024×1536 (portrait, 9:16 for vertical video). Size is fixed — cost scales by model and quality only.
